## 1. 概要

企業が抱える課題と、それを事業として解決したい起業家or起業を考えている人をつなぐマッチングプラットフォーム。
サービス名は、企業のニーズ(Need)と事業の種(Seed)を持つ起業家を結びつけることに由来する。

## 2. 背景・課題

### 企業側の課題
- 人手やノウハウが不足し、手をつけられていない課題を抱えている
- 外部に相談したくても、誰に頼めばよいかわからない

### 起業家側の課題
- 事業アイデアが本当に需要のある課題に基づいているか確かめにくい
- 最初の顧客を見つけるのが難しい

### 両者の関係
企業と起業家or起業を考えている人は互いを必要としているが、課題を起点に出会える場が少ない。

## 3. 目的

企業の課題を起点に起業家or起業を考えている人が事業を生み出せる場を提供し、
企業の課題解決と新しい事業の創出を同時に実現する。

## 4. ターゲット

| 利用者 | 想定する人物像 | 目的 |
| --- | --- | --- |
| 企業担当者 | 従業員50名以下の中小企業の経営者・経営企画担当 | 社内で解決できない課題を外部の力で解決したい |
| 起業家or起業を考えている人 | 起業準備中の会社員・学生、創業間もない起業家 | 実在する課題と最初の顧客を見つけたい |
| 運営者 | プラットフォームの管理者 | 安全で健全なマッチングの場を維持したい |

## 5. 提供価値

- **企業**：課題を登録するだけで、解決に意欲のある起業家or起業を考えている人から提案を受けられる
- **起業家or起業を考えている人**：実在する企業の課題を起点に事業を考えられ、最初の顧客候補とつながれる

## 6. 主な機能(概要)

1. 企業による課題の登録・公開
2. 起業家or起業を考えている人による課題の検索・応募
3. 企業による応募の承認・却下
4. 承認後のメッセージのやり取り
5. 運営者によるユーザー・投稿の管理

※ 詳細な機能と各リリースの範囲は要件定義書(requirements.md)で定める。

## 7. 類似サービスとの違い

| 種類 | 主な目的 | NeedSeedとの違い |
| --- | --- | --- |
| 求人サイト | 人材の採用 | 雇用ではなく、課題解決を事業として行う関係をつくる |
| 副業・業務委託マッチング | 業務の外注 | 作業の依頼ではなく、事業化を前提とした課題解決 |
| オープンイノベーション系サービス | 企業同士の連携 | 個人の起業家を主な対象とする |

## 8. 前提・制約

- 個人開発のポートフォリオとして作成し、実際の集客や営業は行わない
- 登録情報はそれぞれのユーザーが自分で入力する
- デモ用に架空の企業・起業家のデータを用意する
- 開発期間：MVPまで3か月

## 9. プロジェクトの目標

### 学習面
- 企画から運用まで、開発の一連の工程を経験し、各工程の成果物を残す

### 技術面
- 権限管理、状態遷移、公開範囲の制御など、業務システムで求められる設計・実装を行う
- テスト、CI、コンテナ、クラウドへのデプロイまで一通り実施する

### キャリア面
- フリーランス案件の獲得につながるポートフォリオとして完成させる

## 10. 技術スタック(予定)

| 分類 | 候補 | 理由 |
| --- | --- | --- |
| 言語 | TypeScript | フロントとバックエンドを1つの言語で書け、型によって設計の意図をコードに残せるため |
| バックエンド | Next.js(Route Handlers / Server Actions) | フロントと同じリポジトリでAPIを実装でき、個人開発でも一貫した構成を保てるため |
| フロントエンド | Next.js(App Router) | 実務での採用例が多く、Server Componentsによる表示の最適化も学べるため |
| 認証 | Supabase Auth | Supabaseと統合されており、ユーザー情報とDBの権限制御(RLS)を連携させやすいため |
| ORM | Prisma | スキーマ定義からマイグレーションと型を生成でき、DB設計をコードで管理できるため |
| データベース | PostgreSQL(Supabase) | 実務で広く使われるRDBであり、行単位のアクセス制御(RLS)で権限設計を表現できるため |
| インフラ | Vercel(Hobby) + Supabase(Free) | Next.jsとの相性が良く、無料枠で本番環境を公開・運用できるため |
